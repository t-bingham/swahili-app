🔬 Swahili App — Review Research & Justification

The reasoning, evidence, and sources behind every recommendation in the action plan.
Review date: 15 June 2026 · Companion to plan.html
How this review was run. A senior reviewer coordinated four parallel lenses, then cross-validated the findings:
  • Live learner simulation — the app was driven in a browser (onboarding → home → learn session → all tabs) as a first-time beginner. Auth, onboarding, first-exposure cards, reveal/feedback, and every screen were exercised directly.
  • Swahili linguistics audit (specialist agent) — dumped and analysed the seed curriculum public/swahili_default.db by tracing generator templates exhaustively rather than spot-checking random cards.
  • Pedagogy & competitor research (specialist agent) — grounded recommendations in the SLA/SRS literature and a scan of Clozemaster, Anki/FSRS, Memrise, Drops, Language Transfer, Duolingo.
  • Code & accessibility audit (specialist agent) — read the source for WCAG 2.1 AA conformance, correctness bugs, and maintainability; confirmed a clean build.

1 · The headline findingContent correctness outranks everything else

The app's structure is sound, but a language-learning product's core promise is that what it teaches is correct. The single most important discovery of this review is that it currently is not, for the generated grammar tracks.

All 25,353 cards are machine-generated (18,180 conjugation, 4,508 grammar, 2,665 vocabulary). The hand-curated vocabulary is excellent. But two generator bugs produce thousands of incorrect forms — and because they're template-driven, the same error repeats identically across ~159 verbs and dozens of nouns.

Senior validation. Before ranking this #1, I queried the seed DB directly. The results confirmed the audit exactly:

sisoma | I [neg present] to read  → should be sisomi
silisoma | I [neg past] to read  → should be sikusoma
simesoma | I [neg perfect] to read  → should be sijasoma
siku nbaya | bad days  → should be siku mbaya
siku nkubwa | big days  → should be siku kubwa

Counts confirmed by query: 3,636 negative-conjugation cards and 1,053 adjective-concord cards carry certain errors — ~4,700 in total.

2 · Phase 0 — curriculum correctnessWhy these are blockers, and why they're cheap to fix

P0.1Negative-tense conjugations

Bantu verb negation is rule-governed and unambiguous. The generator misses three rules: the negative present changes the final -a → -i (so sisoma must be sisomi); the negative past marker is -ku- not -li- (sikusoma, not silisoma); the negative perfect ("not yet") marker is -ja- not -me- (sijasoma, not simesoma). A side effect of the present-tense bug: generated husoma (2nd-sg negative) collides with the habitual husoma — impossible in correct Swahili, where the -i ending disambiguates. Because affirmative conjugations (including the hard monosyllabic and subjunctive cases) are correct, the fix is localized to three template rules + a regenerate.

Confidence: Certain. Evidence: Wiktionary: Swahili verbs · 2Seeds Swahili — negations

P0.2Adjective–noun concord

Swahili adjectives agree with their noun's class via prefixes, and the rules involve nasal assimilation and animacy — not literal letter-prepending. n + baya → mbaya; n drops before k (kubwa), so nbaya and nkubwa are non-words. Animate nouns (people) take human (M-Wa) concord regardless of class, so daktari mzuri, not daktari nzuri. Class-5 takes a zero prefix for these stems (gari zuri), and abstract U-class nouns pattern with class-3 m- (upole mzuri, flagged Likely pending a native check). Implementing real concord (assimilation + animacy override + class-5 zero + U-class mapping) fixes all ~1,000 cards at once.

Confidence: Certain (N-class/animacy/class-5), Likely (U-class). Evidence: Baylor — noun classes & agreement · UW–Madison — noun-class agreement

P0.3 / P0.4Monosyllabic forms & minor cleanups

Monosyllabic verbs (la, ja, kunywa) compound the negative bug and need stem-specific handling (hali, hajala; subjunctive aje not akuje — reference-confirmed). Lower-severity: prefer standard ndiyo over ndio; the invariant habitual husoma shouldn't be split into six per-person cards (it doesn't mark person); and cross-unit duplicate words (kiti ×4 etc.) inflate the deck.

Evidence: -KU- and monosyllabic verbs

P0.5Why a native-speaker pass still matters

Generator fixes should be verified empirically. A short native/advanced-speaker spot-check of the regenerated negatives and concord (and the "Likely" U-class forms) is cheap insurance against a second template bug before these tracks are declared teaching-ready.

3 · Phase 1 — correctness & data bugsSmall fixes, real user impact

P1.1Star state can be lost on review

In upsertCardState (db.ts:941–966) the ON CONFLICT DO UPDATE SET clause omits starred. Reviews call this on every rating; the INSERT path sets the star but the conflict path won't update it, creating an inconsistency where star changes made elsewhere can be silently dropped. One-line fix (starred = excluded.starred) or remove starred from the upsert entirely.

P1.2FillInBlank can accept any answer

The correct answer is reconstructed by subtracting the before/after strings from the example sentence (FillInBlank.tsx:23–25). String.replace only removes the first occurrence, so repeated substrings break extraction; worse, when extraction yields an empty string the card marks any input correct — a silent correctness failure in a learning exercise. Store an explicit answer field or anchor with a regex, and guard the empty case.

P1.3Biased multiple-choice ordering

[...arr].sort(() => Math.random()-0.5) is a well-known non-uniform shuffle; distractor positions become predictable, which can let learners pattern-match position instead of meaning. Fisher–Yates is the correct, equally simple choice.

P1.4The OAuth popup loop (observed live)

During the live review, ending a session and reloading triggered the Drive sync, which attempted a Google Identity popup with no valid token and logged [GSI_LOGGER] Failed to open popup repeatedly — enough to wedge the page renderer. Background sync should only run with an already-valid silent token and should never trigger an interactive popup except on explicit user action, with back-off on failure. (This also makes the app testable in sandboxed/popup-blocked environments.)

4 · Phase 2 — pedagogical upgradesThe biggest learning gains, mostly on data you already have

The research consensus across the SLA/SRS literature points to two strategic gaps versus best-in-class competitors: sentence-level input and teaching grammar as a generative system. Both are achievable with the existing schema (example_sentences, noun_class).

P2.1Sentence-level cloze — the marquee feature

Clozemaster's core thesis is that words learned in isolation stay in isolation: cloze-in-context delivers comprehensible input (i+1) and retrieval practice in a single exercise. This is the highest-leverage change because the data already exists — a fill_blank mechanism is present; generalising it to blank the target word inside a vocabulary card's example sentence is UI + scheduling work, not a data-generation project.

Evidence: Clozemaster — sentence mining · cloze & comprehensible input · comprehensible-input theory: Conti (2025) on 95–98% comprehensibility

P2.2Noun-class concord as a generative pattern

Every serious Swahili pedagogy source converges on the same advice: don't memorise nouns one at a time — start with the most frequent classes, group semantically, always pair singular+plural, and drill agreement (adjective, verb subject prefix, possessive) across classes. Mastery lives in generating the concord. A "fill the agreeing prefix" exercise plus a class-overview reference chart turns the app's biggest content liability (concord) into a teaching strength — and dovetails with the P0.2 fix, since both need a correct concord-rule table.

Evidence: Baylor Elementary Swahili · noun-class guide

P2.3Tune FSRS desired retention

Among FSRS parameters, desired retention dominates outcomes. Community consensus and the FSRS maintainers put the efficiency sweet spot at ~0.85–0.90: it minimises total study time while keeping recall high, whereas 0.95 roughly doubles daily reviews and 0.97 quadruples them. For a self-study app where burnout is the main churn risk, defaulting to ~0.88 (and optionally surfacing an auto-computed minimum) is a low-effort, high-impact knob worth verifying in fsrs.ts.

Evidence: FSRS — optimal retention · Anki FSRS FAQ

P2.4Interleave skill categories

The "desirable difficulties" trio (spacing, retrieval, interleaving) is the best-established finding in vocabulary learning, and 2024 work shows interleaving layered on spaced repetition produces larger gains and better long-term retention than spacing alone. The app already spaces and retrieves; adding an anti-clustering pass to the weighted draw (so a session doesn't run long streaks of one skill tag) captures the third leg cheaply.

Evidence: CALL-EJ 2024 — interleaving + SRS · Eton CIRL summary

P2.5Elaborative feedback

The corrective-feedback literature ranks elaboration (the why, with an example) above correction (the right answer) above bare verification (right/wrong). The app already shows a "Remember it with:" example on errors; the next step is to surface the relevant concord/tense rule as primary content on rule-based errors, and to elicit self-correction for already-learned forms rather than just revealing.

Evidence: Feedback types & L2 learning · timing of corrective feedback

P2.6Why exercise variety is missing

The prior review noted sessions felt monotonous (type-answer / limited variety). The code audit located the cause: the scaffold function in afm.ts clamps level to 3 for any card at depth ≤ 3, which caps mature-but-not-deep cards at multiple-choice. Re-balancing the clamp (and adding a dev-only badge showing exercise type + scaffold level) lets cloze and type-answer appear when earned — and is the natural home for the new cloze/concord exercises.

Source: code audit (afm.ts:22–27, LearnScreen.pickExercise); receptive-before-productive ordering is itself correct (receptive/productive acquisition).

5 · Phase 3 — audioThe clearest competitive gap

Vocabulary apps over-index on receptive recognition; audio in/out is where Memrise and Duolingo pull ahead, and the app currently ships no audio. Swahili's phonemic spelling and lack of tone make this unusually tractable.

P3.1Browser TTS — but detect the voice

SpeechSynthesis with lang="sw" works with zero backend, and Swahili is among Chrome desktop's voices. The catch the research flags: voice availability is OS/browser-dependent and many devices have no Swahili voice, where the browser silently falls back to an English-accented reading — actively miseducating pronunciation. So the SpeakButton must feature-detect (getVoices().some(v => v.lang.startsWith('sw'))) and hide/disable itself when no real Swahili voice exists.

Evidence: SpeechSynthesis browser support · TTS language/browser compatibility

P3.2Pre-generated cloud-TTS assets

For uniform quality, pre-generate per-card audio offline with a higher-quality engine (Google Cloud TTS and Azure Neural TTS both list Swahili) and ship MP3s as static assets cached by the service worker — a perfect fit for the Vercel static-site + PWA model, with browser TTS as the fallback. Native-speaker clips (Memrise's edge) are the eventual ceiling but are a content-sourcing project, not engineering.

Evidence: Google Cloud TTS voices · Memrise native clips

7 · Phase 5 — motivation & retentionDesign for SDT, not points

The motivation research is unambiguous: durable engagement comes from satisfying autonomy, competence, and relatedness (Self-Determination Theory). Gamification helps when it delivers competence feedback and meaningful choice, and backfires when points/badges become controlling — there is a documented case of gamification misuse reducing motivation in a language app. Concretely:

  • Streaks with a safety valve. Streaks drive retention (Duolingo: restoration +8% retention) but only because freeze/repair relieves anxiety — streak freeze cut churn 21%, while punitive streaks cause burnout and "streak creep." If the app turns on the existing Streaks & XP setting, ship freeze/repair simultaneously.
  • Honest progress (competence). Show mastery growth, not curriculum size — the Stats "not yet seen" relabel was exactly right; keep emphasising personal progress over the intimidating total card count.
  • Dialect labelling (relatedness/expectations). A one-line note that the target is Standard Swahili (Kiunguja/Zanzibar coastal basis) sets correct learner expectations at trivial cost.

Evidence: SDT & gamification (Frontiers 2024) · streak creep · NN/g — autonomy/relatedness/competence · Standard Swahili

8 · Phase 6 — maintainabilityPay down before scaling

These don't affect learners today but will slow every future change. The two that matter most:

  • Migration version can't be incremented safely. A single LEGACY_MIGRATION_VERSION = 1 gate fronts a 390-line monolithic block; new migrations are easy to add in a way that bypasses the version check and runs on every open. Establish a sequential, numbered migration array before the next schema change — and Phase 0's regenerate plus several Phase 2 features are schema-adjacent, so this should come first among the maintainability items.
  • db.ts is 1,757 lines. ~400 lines of content-transformation helpers used only by migrations should move to their own module to make the data layer navigable and testable.

Lower-priority: move the exercise setTimeout reveal delay into LearnScreen's phase transition (removes a keyboard race + rating-button flash), debounce gallery search, and tidy minor smells (duplicate !register check, overlapping depthWeight branches, mode/activeMode duplication).

Source: code audit (Q-01…Q-15 in review/code-a11y.md).

9 · What to keepGenuine strengths the plan deliberately doesn't touch

  • Onboarding flow. Four clear steps, sensible defaults, in-context explanations, working back-navigation, and a no-pressure placement test ("stops as soon as you miss 5"). One of the strongest parts of the app.
  • Hand-curated vocabulary. Natural multi-sense glosses (kali = "sharp / spicy / fierce / strict"), correct noun-class tags, and authentic East-African register (shikamoo/marahaba, ugali). No remediation needed.
  • Sound learning architecture. FSRS scheduling, a scaffolded exercise ladder (correctly receptive→productive), a dedicated grammar track, syllable guides on first exposure, and goal-weighted session assembly.
  • Clean engineering baseline. Strict TypeScript, zero build errors/warnings, a 412 kB bundle, and most prior-review accessibility items already shipped.

The plan is intentionally surgical: fix what's wrong (Phase 0–1), add the few high-ROI features the foundation makes cheap (Phase 2–3), and polish (Phase 4–6) — without rewriting what already works.
