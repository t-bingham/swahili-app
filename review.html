Code Review: Multilingual Learning App

A static engineering review of the current local-first language app, focused on stability, curriculum review, multilingual readiness, offline strategy, and maintainability.

Created: 17 June 2026 · Artifact: static review plan · Scope: no React route, no app behavior changes

Summary

Overall state: the app is buildable and structurally promising. The local-first architecture, language adapter direction, and seed database separation are good foundations. The next work should stabilize tests, close the curriculum review loop, and finish the multilingual/offline story before broader native or backend migration work.

What This Review Is For

This page is a planning artifact for future implementation. It collects review findings into priorities so fixes can be scheduled without mixing analysis, implementation, and product decisions in one pass.

The review intentionally does not propose a cloud rewrite. It assumes the current no-cost local-first PWA remains the right validation architecture while friends and fluent speakers test the app.

P0 Findings

P0Correctness

Test Suite Is Stale

tests/database-regression.test.ts still expects migration bookkeeping strings inside src/database/db.ts, but migrations now live in src/database/migrations.ts. The app builds, but the regression suite no longer reflects the architecture.

  • Update migration-source tests to inspect migrations.ts.
  • Keep the seed DB schema/content checks.
  • Update project docs that still claim there is no test suite.
P0Curriculum QA

Curriculum Review Is Not Seed-Database Complete

The in-app review screen edits the user's local IndexedDB clone. It can export a correction patch, but there is no importer that applies approved corrections back into public/*_default.db.

  • Add target-language text editing for review, not only English/pronunciation/register/cultural note.
  • Add a patch importer script that applies approved JSON patches to the correct seed DB.
  • Add migration support for already-cloned user DBs when approved content fixes must propagate.
P0Sync

Multilingual Sync Remains Swahili-Only

Drive sync currently stores one swahili.db file and only runs for language sw. This avoids overwriting Korean or Maori data, but it also means non-Swahili progress is local-only.

  • Use per-language Drive filenames such as sw.db, ko.db, and mi.db.
  • Include language ID in sync keys and sync UI labels.
  • Document the transition path so existing Swahili Drive users keep their current backup.

P1 Findings

P1UI

Settings Shows Duplicate Review Entry In Dev

The visible Curriculum Review section was added, but the older dev-only Card Review Pipeline button remains. Development builds show the same review entry twice.

  • Remove only the duplicate dev-only review button.
  • Keep Reset account data behind import.meta.env.DEV.
P1Offline

Offline/PWA Strategy Needs Language-Pack Cleanup

The manifest is still branded as Swahili, and the PWA currently risks caching all DB files through the Workbox glob. This is acceptable for a prototype, but it does not match the future "download language/unit packs" model.

  • Rename app manifest branding to a multilingual product name when appropriate.
  • Decide whether first install should cache all language DBs or only selected packs.
  • Design unit-pack download metadata before Capacitor packaging.
P1Data Model

Schema Names Are Still Swahili-Shaped

Shared card fields still use names like swahili and example_sentences[].swahili. The adapter layer hides much of this, but new code still accesses raw fields in several places.

  • Keep DB columns unchanged for now to avoid migration churn.
  • Use adapter methods in UI code wherever possible.
  • Plan a future compatibility migration to target_text only if the app commits to a larger schema cleanup.
P1Language Adapters

Some Screens Still Bypass The Adapter Layer

UnitLessonScreen, parts of ReviewScreen, the Card Gallery conjugation UI, and some helper text still assume Swahili grammar or raw target fields.

  • Route target text, examples, grammar labels, and special drill labels through language adapters.
  • Avoid adding new language.id branches in shared screens unless the branch controls navigation or availability.

P2 Findings

P2Review Flow

Review Save Flow Is Optimistic

handleSave() calls saveReviewedCard() without awaiting it and has no error state. Direct-card review can also mark handwritten cards as reviewed, which may blur generated-review status with seed correction status.

P2Docs

Documentation Is Stale

README.md still presents the project as a Swahili-only no-account app. AGENTS.md says there is no test suite even though tests/ exists. Older review docs contain fixed issues and should be marked historical or superseded.

P2Maintainability

Database Layer Is Large And Multi-Concern

db.ts still owns SQL.js initialization, IndexedDB storage, query helpers, review helpers, and remote merge logic. It works, but it is getting heavy.

  • Split only after current feature churn slows.
  • Suggested future modules: storage/opening, learning queries, review queries, sync merge, and migrations.
P2Privacy

Auth Tokens Live In Local Storage

Google token/profile data is stored in localStorage. This is acceptable for a prototype, but should be documented as a risk if the app becomes a broader product.

Implementation Roadmap

Phase 1: Stabilize The Review Baseline

  1. Update stale DB regression tests.
  2. Remove duplicate Settings review entry in dev.
  3. Refresh AGENTS/README references to tests and languages.

Phase 2: Make Curriculum Review Seed-DB Capable

  1. Add full correction fields, including target text and examples.
  2. Export structured patches consistently.
  3. Add an importer that applies approved patches to the selected seed DB.

Phase 3: Complete Multilingual Sync And Offline Packs

  1. Add per-language Drive sync files.
  2. Decide whether all languages or selected packs are cached.
  3. Align PWA branding with the multi-language product direction.

Phase 4: De-Swahilify Remaining Shared UI

  1. Move remaining raw target text access behind adapters.
  2. Replace Swahili-only helper text in shared screens.
  3. Keep DB schema migration optional until the product direction is firmer.

Phase 5: Maintenance Cleanup

  1. Address the Vite chunking warning if bundle size becomes a real issue.
  2. Split db.ts by concern after the review workflow settles.
  3. Document auth/privacy tradeoffs before broader public testing.

Strengths

Good Foundations

  • Local-first architecture: strong fit for low-cost testing and offline study.
  • Seed DB separation: curriculum is separate from per-user progress.
  • Language adapter direction: the right abstraction for Korean, Maori, Swahili, and future languages.
  • Production build: the app builds successfully despite active feature work.
  • Metadata validation: generated content now has a safety check.
