What Changed

  • Fixed a startup migration bug in src/database/db.ts where grammar seed syncing wrote to a non-existent cards.en column. It now writes to the real cards.english column.
  • Added explicit database flushing after startup migrations and at session finish, reducing the chance that recent review/session data remains only in memory.
  • Fixed quick-learn consecutive-correct accounting in src/store/sessionStore.ts so one correct review increments the counter once, not twice.
  • Fixed gallery status filtering so "new" cards can be queried correctly, then added a visible "New" filter tab in src/screens/CardGalleryScreen.tsx.
  • Added schema_migrations tracking so the legacy migration/content repair bundle runs once per user database instead of being repeated on every open.
  • Replaced the first standalone regression script with a Vitest suite covering utilities, FSRS, scheduling, migration tracking, gallery "New" filter support, and bundled SQLite schema expectations.
  • Split grammar out of the Units screen into its own /app/grammar tab, with vocabulary units and grammar units now numbered independently from 1 in their own tracks.

Why It Matters

  • The migration typo could prevent existing or first-run databases from opening once that migration executed, making it the highest-risk issue found.
  • The flush improvements make the local-first persistence model more reliable, especially after completing a session or after migrations update a user DB.
  • The quick-learn counter fix keeps promotion behavior aligned with actual learner performance rather than accidentally accelerating cards.
  • The gallery fix makes the data API and UI consistent, so learners can inspect unseen cards instead of only introduced cards.
  • Version tracking gives future schema work a clear place to evolve, which is the first step toward separating migrations from ordinary database access.
  • Vitest gives the project a normal test workflow that can grow into integration and component coverage.
  • A separate Grammar tab makes the curriculum model clearer: vocabulary progression stays in Units, while grammar progression has its own route, labels, and back-navigation.

Automated Test Suite

The app now has a fast Node-based Vitest suite. It deliberately starts with the areas that can break learner data or scheduling behavior without needing a browser.

  • tests/utils.test.ts: text normalization, unit unlock status, lesson chunk/status behavior, and rebased vocabulary/grammar track numbering.
  • tests/fsrs.test.ts: FSRS stability, difficulty, retrievability, and learning interval behavior.
  • tests/sessionAssembly.test.ts: card weighting, overdue priority, new-card draw behavior, and immediate-repeat exclusion.
  • tests/database-regression.test.ts: migration typo regression, migration version tracking, gallery "New" filter support, and seed DB schema/content checks using sql.js.

How To Run Tests

  • npm test: runs the full automated test suite once. Use this before committing or after changing scheduling, database, lesson, or algorithm code.
  • npm run test:watch: starts Vitest in watch mode while you are actively developing. It reruns affected tests as files change.
  • npm run build: still run this before release; it type-checks the app and creates the production Vite/PWA bundle.

A good local verification loop is: make a change, run npm test, then run npm run build before sharing or deploying.
